# Blocking stdin prompt in the browser

_2026-10-12 12:01:46_

Browser stdin reads block the worker in Atomics.wait on a SharedArrayBuffer (worker.js readStdin). Before blocking the worker flushes output to the page, which switches to a stdin> prompt: Enter sends a line, Ctrl+D sends the typed text then EOF (sticky for the rest of that submit). Wasi.stdin is the host hook; the default is EOF, which is also the fallback when the page is not cross-origin isolated. netlify.toml and the new www/serve.py send COOP/COEP. Session now routes the echo transcript through Backend::write_output so program output and transcript stay ordered in one buffer that can be flushed mid-submit. Verified by hand in headless chromium over CDP; browser-session.mjs covers the Wasi.stdin hook. Bead nassau-i4g tracks an automated browser check.
